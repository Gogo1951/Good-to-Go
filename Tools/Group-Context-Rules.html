Group Context Rules

One way to answer "where am I right now?" for every feature that turns on or off by group, so a battleground stops being a raid in disguise.

Why this came up

Buff Duty in battlegrounds

Most likely cause · not yet confirmed in game

Your When to Show settings are not the problem. In a battleground the group is a raid, so Buff Duty reads your Raid row, which you have on Always. It never gets that far, though. Before it asks about Solo, Party or Raid, the refresh hides the window whenever the game makes buffs unreadable to add-ons (ns.AreAurasSecret(), Buff-Duty.lua:118). WoW Forever does that in PvP instances, so the window stays hidden whatever the settings say.

To confirm, stand in a battleground out of combat and run this. true means this is the cause.

/run print(C_Secrets.ShouldAurasBeSecret())

If it prints true, no settings change can bring the window back on Forever, because the add-on can't see who is missing what. Rule R12 below covers that case: the options should say so instead of leaving a ticked box that does nothing. Vanilla, TBC and Mists have no secret auras, so there Buff Duty works in battlegrounds today.

The core idea

Four contexts, checked top to bottom

You are always in exactly one context. The first test that passes wins, so a 40-player battleground raid is a Battleground, never a Raid.

1
Battleground
Inside a battleground or an arena: IsInInstance() type is "pvp" or "arena". This is the existing ns.IsInPvPInstance().
2
Raid
In a raid group: IsInRaid(). Home or instance group, LFR included.
3
Party
In a group that isn't a raid: IsInGroup(). Group finder dungeons included.
4
Solo
Everything else. Not in any group.
The rules

What every feature follows

  1. One question, one answer. Any feature that turns on or off by group asks which context you are in, and gets exactly one of Solo, Party, Raid or Battleground.
  2. Precedence is fixed: Battleground, then Raid, then Party, then Solo. Nothing overrides it per feature.
  3. Battleground means a PvP instance. Battlegrounds and arenas count. World PvP, being flagged, or queueing outside the instance does not; you are whatever your group makes you.
  4. Four checkboxes, same order, same labels: Solo · Party · Raid · Battleground. The header is When to Show for windows and When to Use for macros and automation. Each tooltip states the test from the ladder above in plain words.
  5. A tick means "on here." Ticked contexts are on, unticked are off. If nothing is ticked, the panel shows a red line saying the feature will never act.
  6. Default is all four ticked. A feature may start with fewer only for a stated reason, written in its defaults comment.
  7. Extra filters narrow, never replace. Where a feature needs more (Buff Duty's Anywhere / In Instance, consumables' level filter), it's a separate control beside or below the checkboxes. It can only switch a ticked context off. Battleground never gets an In Instance filter, since it always is one.
  8. One helper owns the answer. ns.GetGroupContext() returns the context, and ns.IsGroupContextOn(settings) reads the ticks. No feature calls IsInRaid() to decide its own visibility. Plumbing that only picks a chat channel or a unit prefix (raid1 vs party1) is exempt.
  9. Re-check on every change of place or group: GROUP_ROSTER_UPDATE, PLAYER_ENTERING_WORLD, ZONE_CHANGED_NEW_AREA. The macro group signature includes the context, so entering a battleground rescans.
  10. Settings share one shape: showIn = { solo, party, raid, battleground }, booleans. Saved under each feature's own table, never shared between features.
  11. Updating changes nobody's behaviour. A new Battleground tick copies whatever the old setting did in a battleground, which was the Raid answer. See the migration table.
  12. Never ignore a tick silently. If a feature can't work in a context on some client (Buff Duty in a Forever battleground), that checkbox is greyed out with the reason in its tooltip. If the game blocks it mid-session, say so once in chat.

Code shape

The one helper

-- Features/Utilities.lua  (rules R1 to R3, R8)
ns.GROUP_CONTEXTS = { "solo", "party", "raid", "battleground" }

function ns.GetGroupContext()
	if ns.IsInPvPInstance() then return "battleground" end
	if IsInRaid() then return "raid" end
	if IsInGroup() then return "party" end
	return "solo"
end

-- settings.showIn = { solo = true, party = true, raid = true, battleground = true }
function ns.IsGroupContextOn(showIn)
	return showIn[ns.GetGroupContext()] ~= false
end
Your call

Open questions

Do arenas count as Battleground?

Recommend yes. Both are PvP instances where you buff before the gates open. The tooltip says "battlegrounds and arenas." The alternative is a fifth box, which is what the nut asks for next.

Keep Anywhere / In Instance on Buff Duty?

Recommend keep it on Solo, Party and Raid only. Dropping it loses "only in dungeons," and people who set it today would lose that on update.

Move the consumable dropdowns to checkboxes?

Recommend yes, with the level filter split out. Four rows of four boxes is more panel, but it's the same control everywhere, and group plus level can finally combine.

Buff Duty's Battleground box on Forever

Recommend greying it out once the /run check confirms secret auras, rather than trying to show a window that can't tell who needs buffs.
